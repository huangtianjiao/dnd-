AI 跑团全网调研报告

调研时间: 2026-07-13 | 覆盖: 英文社区 (Reddit, OpenAI Forum, Oracle-RPG, wilds.ai) + 中文社区 (网易, bilibili, 机核, Dicecho) + MCP 生态

一、核心结论：三条路线

全网实践者的共识：AI 跑团能否持续可玩，取决于一个关键节点——Session 3。三轮之后，上下文窗口开始溢出、状态追踪开始混乱、叙事开始断裂。三条路线的分化正围绕这个问题展开。

路线 A 纯 Prompt

直接把 ChatGPT / Claude / Gemini 当 DM，靠系统提示词约束行为。

优势: 零成本、零部署、任何 LLM 都能用、叙事质量最高

致命缺陷: Session 3 后记忆崩塌——Gemini 实测报告显示第一小时完美，一小时后开始反刍旧对话并编造剧情，40% 的内容脱离模组设定，完全忘记应当触发 SanCheck。ChatGPT 同样在超过 ~6000 词后裁剪早期上下文。

适用场景: 一次性短团（1-2 session）、叙事实验、新手入门

路线 B 专用平台

Fables.gg、wilds.ai、DungeonsDeep.ai、AIDungeonMaster.ai 等。

优势: 内置确定性骰子引擎、HP/法术位自动追踪、地图渲染、NPC 好感度持久化。wilds.ai 实测 Session 2 结交的商人在 Session 5 主动提供稀有物品。

缺陷: Fables 锁定 5e 且记忆跨 session 不稳定；DungeonsDeep 用自研规则集而非原生 5e；多数平台不支持中文；$9-39/月。

适用场景: 英文环境下的长期单人跑团

路线 C MCP 工具链

ChatRPG、DnD-MCP 等 MCP Server，作为 AI 的"手"执行确定性操作。

优势: 30+ 专用 5e 工具（角色创建、战斗管理、骰子、空间计算、法术追踪）全部确定性执行。状态持久化到本地文件。配合规则书 RAG 效果极强。免费。

缺陷: 需本地部署 Node.js/Python、ASCII 地图不如可视化 VTT、仍在快速迭代中。DnD-MCP 声称 90+ 工具但文档较新。

适用场景: 你的最佳路线——有本地规则书库、有 WorkBuddy 环境、中文可用

二、Gemini 100 万词元实测——AI 跑团的"照妖镜"

实验概要

一位玩家使用 Gemini 1.5（100 万词元上下文）作为 KP 跑 CoC 模组《我的色彩》。这是目前公开的最详细的 AI 跑团实测记录。

第一小时：完美

  • 雪山氛围渲染到位，NPC 切换流畅
  • 主动要求 SanCheck 和投掷，沉浸感十足
  • 根据角色卡调整 NPC 表现——真正"读懂"了模组

一小时后：全面崩塌

  • 反刍旧对话: 不断把之前已经完成的剧情重新"解压"到当前回复中，导致对话越来越长越来越乱
  • 剧情错乱: 玩家选择独自上山，Gemini 后来认为玩家和警官一起上山。纠正后反而反刍了从出院开始的整段剧情
  • 遗忘 KP 职责: 后期完全忘记需要 roll 点和 SanCheck，退化成"故事接龙"
  • 战斗缺失: 模组有详细战斗场景，Gemini 从未触发任何战斗
  • 大剧透: 将模组高潮直接在半山腰暴露
  • 放飞自我: 约 40% 的剧情量没有跟随模组要求

推测原因

Gemini 可能采用"分幕压缩-解压"策略管理长上下文。这解释了为什么它能定位到早期剧情但会反刍整段——它把历史聊天"压缩打包"，需要时再"解压"，但解压后默认反刍而非精准引用。随着压缩层级增加，"我们在跑团"这个核心身份标签被压缩掉，导致退化。

三、三条长 Campaign 存活的硬指标

wilds.ai 的多轮实测（8 session 深度测试）总结出三个"Session 3 后仍可玩"的硬条件：

1. 确定性机制

骰子掷多少就是多少，AI 不能偷偷改结果。HP 减多少就是多少，不能"忘了"之前扣的伤。

违反 = 玩家失去信任 → 退坑

2. 持久记忆

不是"更长上下文窗口"。是实际持久化: Session 2 结交的 NPC 在 Session 5 记得你。Session 2 的背叛在 Session 6 引发报复。

wilds.ai 用"后果引擎"实现了这一点。

3. 机械状态追踪

HP、法术位、物品栏、任务标记、NPC 声望——如果玩家要手动记这些，那工具就是个聊天框，不是游戏引擎。

目前满足全部三条的只有 wilds.ai 和 MCP 方案。Fables 满足 1 和部分 3 但记忆不稳定。纯 Prompt 方案三条都不满足。

四、Prompt 方案深入——社区精华

4.1 最成熟的 Prompt: Oracle-RPG 三合一架构

由 Pite Raubenheimer 在 oracle-rpg.com 发布，是目前最完整、经过最多实战打磨的 5e AI DM prompt。它解决了之前 AI DM 的三大缺陷：

  • 规则管理需外部处理 → 内置规则框架，AI 自动调用检定
  • 遭遇生成需掷表 → AI 程序化生成遭遇
  • 战斗内容被审核拦截 → 明确"5E 规则集桌面 RPG"框架避免误判

三合一架构

AI DM Emulator
规则框架 + 技能检定 + 遭遇生成
描述生成器
设定 + 沉浸式叙事 + 对话
冒险生成器
任务创建 + 角色确认 + 开场选项

关键约束设计

  • AI 永远不能替玩家描述行动、说话、思考或感受
  • 回复限制 80 词以内——防止反刍膨胀
  • 永远不问"你做什么？"——改为场景描述自然引出行动
  • 战斗时先要求先攻检定，然后按先攻顺序逐回合推进
  • AI 追踪所有战斗人员 HP，攻击检定需达到或超过 AC 才命中
  • 开始前提供三个冒险选项 + 要求角色信息

记忆管理技巧

定期输入"创建到目前为止所有事件的详细摘要"来"存档"。ChatGPT 的 Memory 功能配合使用: "记住这个角色" / "记住这个事件" / "记住这个摘要"。

4.2 中文社区 Prompt 精华

机核版 (Gcores)

基于 Reddit 玩家提示词翻译整合。特色:

  • 用花括号 {} 表示需要掷骰的动作: {说服}公主和我一起逃走
  • 用方括号 [] 表示 OOC 交流: [请解释这个规则的判定]
  • 用引号 "" 表示角色对话
  • 用 x,y 二维坐标系绘制战斗地图，以句号表示玩家、数字表示怪物/NPC
  • 严格按照 5E 规则书奖励 XP、管理等级进展

Bilibili RPG-Bot 版

最结构化的中文 prompt，用 <GAME_MANUAL> XML 标签包裹完整的游戏手册:

  • 定义 GAME / BOOKS / ROLE / THEME / TONALITY / CHARACTER 六层参数
  • 每轮必须提供 5 个潜在行动选项（其中一个随机为"疯狂/危险/天才"选项）
  • 回复长度约束: 1000-3000 字符
  • NPC 必有"易发现秘密" + "难发现秘密"，驱动动机
  • 新一天 / 升级 / 请求时显示角色卡
  • 明确要求"虽然手册是英文，但全程用简体中文交互"

七、针对你的环境的最佳方案

推荐: 路线 C (MCP) + 5echm 规则书 RAG

你的独特优势:

  • 本地有完整 5echm 中文规则书 (8453 文件)——全网独一无二的资源
  • WorkBuddy 支持 MCP 接入——可以直接挂 ChatRPG / DnD-MCP
  • 中文 LLM 对中文叙事质量最高
  • 本地部署 = 零费用 + 数据不泄露

实施路线图

  1. Phase 1: 部署 ChatRPG MCP — 安装 Node.js 依赖，配置 MCP 接入，验证角色创建和骰子掷投
  2. Phase 2: 规则书 RAG — 将 5echm 核心文件 (战斗流程、法术、状态条件) 建索引，供 AI 实时查询而非靠"记忆"
  3. Phase 3: 系统 Prompt 优化 — 融合 Oracle-RPG 三合一架构 + Bilibili RPG-Bot 结构化设计 + 机核语法约定，定制中文版本
  4. Phase 4: Session 测试 — 从入门模组 (松溪险境/矿坑) 开始，每 session 结束强制存档 (get_session_context)

关键设计决策

  • 确定性优先: 所有掷骰、HP、法术位通过 MCP 工具执行，AI 只负责叙事和判断
  • 规则书即 RAG: AI 需要查规则时读文件而非凭记忆——彻底消除规则幻觉
  • 语法约定: {动作} 表示需要检定，[OOC] 表示离场交流，"对话" 表示角色说话
  • 定期存档: 每个 session 结束调用 get_session_context + 写入 memory 文件
  • 80 词约束: AI 回复控制在 80 词内，防止反刍膨胀

八、社区共识的"AI DM 不该做的事"

五条铁律 (来自多源交叉验证)

  1. 绝不替玩家行动 — AI 不能描述玩家角色的行动、说话、思考或感受。这是最频繁的翻车点。
  2. 绝不透露未发现的信息 — 场景开始时不宣布有埋伏，NPC 不应透露玩家还没发现的秘密。
  3. 绝不假设行动成功 — 除非经过检定。简单任务自动成功，不可能任务自动失败，其余必须掷骰。
  4. 绝不强行推进预设剧情 — 优先响应玩家选择，DM 的"剧情计划"只是备选不是强制。
  5. 绝不跳过时间 — 除非玩家明确要求。AI 的"加速叙事"倾向会让玩家失去控制感。
