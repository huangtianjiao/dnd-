# D&D 5e 2024 规则数据治理、测试验收与迁移路线图

审计基线：huangtianjiao/dnd-，master @ 99f4c3499da168a2f447771cfd623916b9666620（2026-07-31）。规则基准：仓库 5echm_web/topics/玩家手册2024、城主指南2024、怪物图鉴2024及项目内结构化规则。

## 1. 为什么必须先建立完成度证明系统

D&D规则面广、例外多。只靠人工阅读“看起来实现了”无法证明完整；当前仓库也已经出现“引擎函数正确但生产resolver绕过”“数据表完整但效果未执行”“文档标记已对齐但真实链路仍有漏洞”的情况。

因此最终产品应把CoverageManifest、规则溯源和自动测试视为规则引擎的一部分，而不是收尾文档。

## 2. 2024语料治理

### 2.1 SourceDocument元数据

```json
{
  "source_id": "phb2024.glossary.conditions",
  "edition": "2024",
  "book": "PHB",
  "language": "zh-CN",
  "path": "5echm_web/topics/玩家手册2024/术语汇编/状态.htm",
  "anchor": "力竭",
  "content_hash": "sha256:...",
  "extractor_version": "2.0.0",
  "authority_level": "primary",
  "review_status": "verified"
}
```

2014、2024、项目说明、房规必须分不同source_class和collection。运行时查询以RulesetManifest硬过滤，而不是在prompt里提醒模型“优先2024”。

### 2.2 RuleDefinition溯源

每条可执行规则必须关联至少一个SourceSpan；复杂规则可关联多个段落。构建时验证路径、anchor和hash。原文变动会产生“需要重新审核”，不得自动覆盖已发布Definition。

### 2.3 RAG用途边界

RAG可用于：解释规则、寻找DM裁定建议、展示来源、辅助内容录入。RAG不得用于：计算AC/DC、决定伤害骰、确认角色熟练、生成怪物HP、直接写状态。

## 3. CoverageManifest

建议格式：

```yaml
content_id: spell.fireball
ruleset_revision: 2024.1
status: VERIFIED
source_spans: [...]
handlers:
  - spell.cast
  - effect.damage
  - save.dex_half
  - area.sphere
unit_tests: [test_fireball_base, test_fireball_upcast]
scenario_tests: [scenario_fireball_cover_resistance]
unsupported_notes: []
```

状态枚举：

- `MISSING`：没有数据；
- `DATA_ONLY`：有原文/数据，无机械；
- `PARTIAL`：部分分支；
- `WIRED`：生产接线但覆盖不足；
- `FULL`：机械覆盖完整；
- `VERIFIED`：FULL且测试、溯源、回放通过。

Complete模式只暴露VERIFIED。开发模式可以显示PARTIAL，但UI必须明确标注。

## 4. 测试金字塔

### 4.1 Schema与内容测试

- 所有canonical ID唯一；
- 所有引用存在；
- 所有规则有2024来源；
- 骰式、范围、持续和效果图合法；
- 低置信度字段不可发布；
- 所有公开内容Coverage状态达标。

### 4.2 纯规则单元测试

固定RNG验证公式和边界：属性调整、PB、优劣势抵消、攻击天然20/1、豁免、伤害、抗性、状态、资源恢复、每种武器词条和精通。

### 4.3 属性/性质测试

- HP永不高于上限且伤害不产生负伤害；
- 同一优势来源数量不叠加成三骰；
- 优势与任意数量劣势抵消；
- 同一命令幂等；
- 资源消耗守恒；
- 完整事件重放得到相同状态；
- 2014规则永不进入2024manifest；
- Condition来源移除不影响其他来源。

### 4.4 场景测试

使用Given/When/Then和固定地图、实体、RNG：

```gherkin
Given 一个装备盾牌但把盾牌收在背包里的角色
When 系统计算AC
Then 盾牌不提供+2
And 解释轨迹不包含shield bonus
```

### 4.5 生产链路E2E

必须从REST和WebSocket入口提交自然语言，经过意图解析、命令构建、领域结算和持久化，再断言数据库和事件。P0规则不能只测内部函数。

### 4.6 并发与故障测试

- 同一回合两个玩家并发动作；
- 同一idempotency key重复请求；
- 提交中途数据库异常；
- WebSocket断线重发；
- Narrator超时；
- RAG不可用；
- 事件投影重建。

规则结算不能依赖Narrator或RAG可用性。

## 6. CI发布门禁

每次提交必须运行：

```text
lint + typecheck
schema validation
source provenance validation
unit + property tests
coverage manifest generation
critical scenario suite
API/WS E2E
event replay tests
2014 leakage test
migration tests
```

发布规则：P0=0；公开PHB内容VERIFIED=100%；DMG/MM内容按声明包VERIFIED=100%；无未知LLM机械回退；事件重放和幂等测试通过。

## 7. 分阶段迁移路线图

### M0：冻结与测量

- 固定当前SHA和数据库备份；
- 生成现状CoverageManifest；
- 将所有现有内容标记DATA_ONLY/PARTIAL/WIRED；
- 建立100场景基线，即使当前失败也先登记。

**退出标准**：可以量化每个领域覆盖率，现有行为可复现。

### M1：封死权威边界

- 删除Director机械字段；
- Narrator只读；
- 未知法术拒绝；
- 修复失败施法扣槽、盾牌背包AC、生命骰0回退、专注NameError；
- 引入idempotency和事务。

**退出标准**：P0中的直接状态篡改和资源错误清零。

### M2：唯一状态与事件内核

- Character/Creature/Combat聚合；
- DomainEvent、EffectInstance、TimingPoint、ModifierTrace；
- 旧resolver适配到Application Service；
- 固定RNG和回放。

**退出标准**：攻击、伤害、状态、法术位可通过事件重建。

### M3：战斗核心FULL

- 地图/可见性/掩护/移动；
- 武器词条、精通、额外攻击、反应；
- 条件和0HP状态机；
- 统一怪物基础动作。

**退出标准**：PHB战斗场景全部VERIFIED。

### M4：施法FULL

- SpellDefinition与Effect DSL；
- 准备/已知/法术位/成分；
- 目标、区域、持续、专注和反应；
- 编译并审校全量PHB法术。

**退出标准**：PHB法术Coverage=100% VERIFIED，无generic占位。

### M5：角色构筑FULL

- Grant/Feature/Choice；
- 12职业、子职、物种、背景、专长；
- 升级与兼职；
- 物品和同调。

**退出标准**：1-20级构筑内容全部VERIFIED。

### M6：DMG/MM运行包

- 怪物完整stat block与传奇/巢穴；
- 探索、旅行、危害、停工期、宝藏和魔法物品；
- RAW/可选规则policy。

**退出标准**：每个宣称支持的内容包100% VERIFIED。

### M7：清理与发布

- 删除旧重复引擎和fallback；
- 迁移所有存档；
- 自动生成玩家规则说明与开发者覆盖报告；
- 性能、并发、故障注入与安全测试。

## 8. 给施工AI的任务协议

每个任务必须提交：

1. 修改范围和规则ID；
2. 原文来源路径与anchor；
3. 数据模型/事件变化；
4. 生产接线路径；
5. 单元和E2E测试；
6. CoverageManifest变化；
7. 存档迁移；
8. 已知限制。

禁止仅新增“辅助函数”而不证明生产入口调用；禁止用LLM兜底未实现规则；禁止手工把状态标记为FULL。

## 9. Definition of Done

一个规则或内容项只有满足以下全部条件才完成：

- 2024来源明确且hash固定；
- 稳定canonical ID；
- schema完整；
- 唯一handler/DSL可执行；
- 权威状态与资源通过事件原子提交；
- 无LLM机械输入；
- 正常、失败、边界、交互测试通过；
- API/WS生产入口测试通过；
- 固定RNG可回放；
- CoverageManifest=VERIFIED；
- 文档由manifest自动更新。
