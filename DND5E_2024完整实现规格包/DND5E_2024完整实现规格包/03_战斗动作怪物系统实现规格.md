# D&D 5e 2024 战斗、动作与怪物系统完整实现规格

审计基线：huangtianjiao/dnd-，master @ 99f4c3499da168a2f447771cfd623916b9666620（2026-07-31）。规则基准：仓库 5echm_web/topics/玩家手册2024、城主指南2024、怪物图鉴2024及项目内结构化规则。

## 1. 范围

本文件定义PHB2024战斗核心以及MM/DMG怪物运行所需的统一机制。目标不是做两套“玩家战斗”和“怪物自动攻击”，而是让所有生物通过同一动作、检定、效果和事件系统行动。

## 2. 战斗状态机

```text
OUT_OF_COMBAT
  -> COMBAT_SETUP（确定参战者、位置、突袭）
  -> INITIATIVE
  -> ROUND_START
  -> TURN_START
  -> TURN_ACTIVE
       [移动段 / 动作 / 附赠动作 / 免费交互 / 子攻击 / 选择 / 反应窗口]
  -> TURN_END
  -> next TURN_START
  -> ROUND_END
  -> COMBAT_END
```

每个转移必须由事件驱动。不能在任意resolver末尾“顺手推进回合”。单人模式可以自动提交EndTurn，但底层语义仍与多人一致。

## 3. 战斗开始与先攻

### 3.1 Setup

- 从Scene/BattleMap获取位置、光照、遮蔽与阵营；
- DM或遭遇定义决定参战者，玩家不能通过文本凭空生成敌人；
- 突袭按2024判断“未察觉危险”并给予先攻劣势；
- 隐形与失能带来的先攻优劣势都作为Modifier来源收集；
- 同组怪物是否共用先攻由EncounterDefinition明确，而不是仅凭group_id默认；
- 平局进入`InitiativeTieChoice`，由规则规定的控制者选择并记录。

### 3.2 先攻事件

```text
InitiativeRollRequested
RollPerformed
InitiativeCalculated
InitiativeOrderChosen（有平局时）
CombatStarted
TurnStarted
```

警戒专长、先攻交换等能力应在相应窗口提供选择，不能硬编码在排序key。

## 4. 动作经济

每回合资源：Action 1、BonusAction可用性、MovementBudget、ObjectInteraction 1；Reaction按自己下回合开始刷新。额外动作等能力通过Resource/Grant增加机会，而非修改布尔值。

动作提交统一经过：

```text
Validate timing -> Validate actor -> Validate cost -> Validate target
-> Build plan -> Open reactions/choices -> Resolve -> Spend cost atomically
```

失能必须在ActionConstraint层阻止动作、附赠动作和反应；不是每个函数各自检查一次。

## 5. 移动与地图

### 5.1 BattleMap

- 坐标和高度；
- 每格地形成本、危险和遮挡；
- 生物footprint与占据；
- 门、墙、物件和区域效果；
- 光照区与感官查询；
- 可选择方格和路径。

### 5.2 MovementPlan

```json
{
  "actor_id": "pc1",
  "mode": "walk",
  "path": [[1,1],[2,1],[3,1]],
  "segments": [
    {"from":[1,1],"to":[2,1],"cost_ft":5,"events":[]},
    {"from":[2,1],"to":[3,1],"cost_ft":10,"events":["LEAVE_REACH"]}
  ]
}
```

每段依次提交或在同一命令内按顺序生成事件。困难地形、匍匐、攀爬、游泳、生物空间叠加按规则计算；不能只对总距离乘一个布尔倍率。

### 5.3 强制要求

- 起立消耗速度的一半并要求速度非0；
- 跳跃受剩余移动限制；
- 不同速度模式切换时按2024规则计算已用比例/预算；
- 不能在敌对生物空间结束移动；
- 强制移动、传送和不消耗自身移动的效果不触发借机攻击；
- 离开触及逐敌人开放ReactionWindow。

## 6. 可见性、感官与掩护

`VisibilityService(observer, target, context)`输出：

```text
visible / located / concealed / hidden
line_of_sight / line_of_effect
cover: none/half/three_quarters/full
reasons: darkness, opaque_wall, invisible, blindsight, truesight...
```

“知道位置”和“能看见”分开。隐形不等于位置未知；隐藏需要Hide成功和后续发现规则。攻击和法术目标分别查询其要求。

## 7. 攻击动作

### 7.1 BuildAttackPlan

输入只允许：actor_id、target_id、weapon_instance_id、玩家合法选择。派生：

1. 武器是否持握/拥有/可用；
2. 攻击类型（近战/远程/投掷/法术武器攻击）；
3. 允许的属性；
4. 熟练来源；
5. 射程、触及、视线、掩护；
6. 优劣势来源；
7. AC来源；
8. 命中后可选与自动触发；
9. DamagePacket。

### 7.2 武器属性handler

| 属性 | 必须执行的逻辑 |
| --- | --- |
| 弹药 | 验证对应弹药、每次攻击消耗、战后回收规则、近战临时武器处理 |
| 灵巧 | 允许力量或敏捷，攻击和伤害必须使用同一属性 |
| 重型 | 按2024属性门槛给予攻击劣势，区分近战/远程 |
| 轻型 | 攻击动作后开放另一轻型武器额外攻击；默认附赠动作成本；每回合限制 |
| 装填 | 无论可攻击次数，动作/附赠/反应中该武器至多一发 |
| 射程 | 常规正常、长程劣势、最大外非法 |
| 触及 | 触及+5并影响借机攻击窗口 |
| 投掷 | 远程攻击但使用该近战武器原允许属性 |
| 双手 | 攻击时必须两手，不必永久占用两手状态以外的交互需按规则处理 |
| 多用 | 单手/双手选择影响伤害骰 |

### 7.3 武器精通

- `Cleave/横扫`：命中后、满足相邻目标、每回合一次，开放额外攻击选择；
- `Graze/擦掠`：失手后固定属性调整值伤害，不能小于规则允许值，仍走伤害类型修正；
- `Nick/迅击`：轻型额外攻击移入攻击动作，不额外增加次数；
- `Push/推离`：命中且体型满足，选择推至多10尺，执行强制移动；
- `Sap/削弱`：给目标下一次攻击劣势，到来源下回合开始前结束；
- `Slow/缓速`：速度-10尺，不叠加，持续到来源下回合开始；
- `Topple/失衡`：命中后体质豁免，DC从本次攻击属性和PB派生，失败倒地；
- `Vex/侵扰`：对该目标的下一次攻击优势，持续到来源下回合结束。

每个精通必须记录角色是否对该武器获得精通，而不是看到武器表有mastery就自动生效。

## 8. 额外攻击、轻型攻击和子攻击

攻击动作创建`AttackSequence`：

```text
sequence_id
remaining_attack_opportunities
loading_weapon_usage
light_weapon_bonus_available
nick_conversion_used
per_turn_feature_usage
```

玩家每次选择一个子攻击，可在子攻击之间合法移动。子攻击独立产生命中和伤害事件。结束动作时未使用机会作废。不能预先汇总total_damage后一次扣血。

## 9. 擒抱、推撞与徒手打击

2024徒手打击命中选择：造成伤害、擒抱、推撞。擒抱/推撞使用目标选择力量或敏捷豁免，对抗`8 + 攻击者力量调整值 + PB`，并验证体型和空手。

受擒必须生成来源关联：

```text
GrappleEffect(grappler_id, grappled_id, escape_dc)
```

拖动、攻击非擒抱者劣势、擒抱者失能/距离变化/被移动等结束条件由Effect系统自动处理。

## 10. 伤害结算

### 10.1 DamagePacket

```yaml
components:
  - source: weapon.long_sword
    dice: 1d8
    type: slashing
    crit_dice: true
  - source: feature.sneak_attack
    dice: 3d6
    type: inherited_weapon
    crit_dice: true
  - source: rage
    flat: 2
    crit_dice: false
```

逐component掷骰，再按需要合并同类型。顺序必须明确：免疫/抗性/易伤、伤害减免、临时HP、HP、0HP状态机。每个伤害源单独触发专注检定。

### 10.2 0 HP状态机

```text
DamageApplied
 -> MassiveDamageCheck
 -> if 0 HP:
      knockout choice? -> 1 HP + unconscious + short rest（2024）
      else unconscious + prone + death tracking
 -> at turn start DeathSave
 -> damage at 0 HP adds failures
 -> healing resets counts and ends unconscious as applicable
```

怪物是否使用死亡豁免由DM/StatBlock policy决定，不能简单“HP<=0=dead”。

## 11. 状态条件完整执行

| 状态 | 关键执行点 |
| --- | --- |
| 目盲 | 依赖视觉的检定自动失败；攻防优劣势；目标可见性 |
| 魅惑 | 不能攻击或伤害魅惑来源；来源社交优势 |
| 耳聋 | 依赖听觉检定自动失败 |
| 恐慌 | 来源可见时攻击/属性检定劣势；不能主动靠近来源 |
| 受擒 | 速度0；攻击非擒抱者劣势；来源关联和拖动 |
| 失能 | 无动作/附赠/反应；专注结束；先攻劣势 |
| 隐形 | 目标要求可见时不可选；攻防修正；先攻优势 |
| 麻痹 | 失能、速度0、力敏豁自动失败、受攻击优势、5尺内自动重击 |
| 石化 | 材质化、重量、停止老化、失能、速度0、力敏豁失败、全抗、毒免 |
| 力竭 | 每级d20-2、速度-5、6级死亡 |
| 中毒 | 攻击与属性检定劣势 |
| 倒地 | 移动限制、起立成本、攻防距离修正 |
| 束缚 | 速度0、攻防修正、敏捷豁免劣势 |
| 震慑 | 失能、力敏豁失败、受攻击优势 |
| 昏迷 | 失能+倒地、掉落手持物、速度0、力敏豁失败、受攻击优势、5尺自动重击、无知觉 |

每个状态均通过EffectInstance跟踪来源和结束规则，不能只保存名称。

## 12. 反应系统

反应是通用窗口，不是单独动作类型。窗口包含：

```text
trigger_event
eligible_reactors
available_reactions[]
priority/controller
deadline/policy（单机可同步，在线可超时）
```

典型窗口：离开触及、攻击命中后伤害前、看见生物施法、盟友受击、豁免失败后传奇抗性。反应选择完成前，不得提交后续不可逆事件。

## 13. 怪物与NPC

### 13.1 StatBlock编译

```yaml
id: monster.example
abilities: ...
ac: {formula: natural_armor, value: 15}
hp: {dice: 7d8+14, average: 45}
senses: ...
damage_affinities: ...
traits: [feature_ids]
actions: [action_definition_ids]
bonus_actions: []
reactions: []
legendary_actions: []
spellcasting_sources: []
```

怪物动作与玩家动作使用同一Effect DSL。AI不得直接写伤害，只选择合法Command。

### 13.2 Monster AI责任

AI输入是合法动作候选和可见状态；输出只包含选择：动作ID、目标ID、移动目的地、可选资源。策略层不能改变规则数值。

最低策略：

1. 生成所有合法行动；
2. 按stat block行为标签评分（近战、远程、控制、逃跑）；
3. 考虑距离、目标可见性和资源；
4. 选择并提交Command；
5. 若触发选择/反应，继续通过同一流程。

## 14. 传奇、充能与巢穴

- 充能：来源回合开始掷骰，成功发布ResourceRestored；
- 传奇抗性：豁免失败后、结果应用前开放可选替换窗口；
- 传奇动作：其他生物回合结束后开放窗口，扣传奇动作点；
- 巢穴动作：绑定Encounter/Lair，在指定先攻时点运行；
- 传说动作和反应不能共享错误的资源池。

## 16. 禁止实现方式

- 禁止从intent读取target_ac、resistance或proficient；
- 禁止怪物回合专用“直接攻击”捷径；
- 禁止用字符串状态和若干布尔字段代替Effect生命周期；
- 禁止把多次攻击汇总成一个damage写事件；
- 禁止在验证完成前消耗动作/反应；
- 禁止用Narrator决定战斗状态变化。
