# D&D 5e 2024 施法、角色构筑与内容系统完整实现规格

审计基线：huangtianjiao/dnd-，master @ 99f4c3499da168a2f447771cfd623916b9666620（2026-07-31）。规则基准：仓库 5echm_web/topics/玩家手册2024、城主指南2024、怪物图鉴2024及项目内结构化规则。

## 1. 总体要求

仓库拥有全量法术原文提取、12职业表、专长文本、装备表等，这是很好的内容基础。但要做到完整实现，必须把“自然语言内容目录”编译成稳定ID、结构化规则定义和可执行Effect图，并用覆盖清单证明没有占位分支。

## 2. 法术内容模型

### 2.1 SpellDefinition

```yaml
id: spell.fireball
revision: phb2024-r1
name_key: spell.fireball.name
level: 3
school: evocation
sources: [wizard, sorcerer]
casting:
  cost: action
  components:
    verbal: true
    somatic: true
    material: {item_or_text: bat_guano_sulfur, cost_gp: 0, consumed: false}
range: {type: distance, feet: 150}
target:
  type: point
  requires_line_of_effect: true
area: {shape: sphere, radius_ft: 20}
duration: instant
save: {ability: dex, success: half_damage}
effects:
  - op: damage
    dice: 8d6
    type: fire
upcast:
  for_each_slot_above: 3
  add: {dice: 1d6}
```

字段必须来自人工审校或高置信度编译；描述文本只用于展示和RAG解释。

### 2.2 TargetSpec

支持：self、creature、willing_creature、object、point、多个目标、每个射线独立目标、可见目标、听得到目标、已知目标、区域内自选目标。必须表达：是否可选自己、是否可重复同一目标、数量随升环变化、是否需要看见、是否受全掩护阻挡。

### 2.3 AreaSpec

支持sphere、cone、line、cube、cylinder、emanation；明确原点规则、边界格、是否绕角、是否随施法者移动、进入/开始回合触发。

### 2.4 DurationSpec

```yaml
type: concentration | rounds | minutes | hours | until_rest | permanent
value: 1
expire_at: source_turn_start | source_turn_end | target_turn_end | clock
repeat_save: {timing: target_turn_end, end_on_success: true}
```

## 3. 法术施展流程

```text
Resolve spell_id and casting source
 -> Verify known/prepared/always-prepared/spellbook/item grant
 -> Verify timing and action/reaction
 -> Choose slot or free-use resource
 -> Validate target, range, sight, area
 -> Validate V/S/M and armor restrictions
 -> Validate material inventory and cost
 -> Build effect plan and upcast substitutions
 -> Open reaction window (Counterspell etc.)
 -> Resolve rolls/choices
 -> Atomically spend action/slot/material and create effects/events
```

失败点在提交前，不消耗任何资源。被反制等“施法已开始后失败”场景按规则产生相应资源事件。

## 4. 法术资源与职业差异

### 4.1 SpellSource

一个角色可有多个施法来源：职业、专长、物种、物品。每个来源声明：施法属性、可用列表、已知/准备规则、法器、免费施展、是否可用其他法术位。

### 4.2 准备/已知模型

```text
SpellbookEntry：法师法术书内容
KnownSpell：术士/吟游诗人等来源
PreparedSpell：当前准备，带source_id
AlwaysPrepared：领域、誓言、物种、专长
GrantedCasting：每日一次/不耗位/物品充能
```

不能使用“known_spells为空就给全部”。旧角色迁移时必须进入待选择状态，而不是自动全给。

### 4.3 法术位

- 全施法者按各职业表；
- 半施法者按本职业进度；
- 魔契术法位独立环阶、数量和短休恢复；
- 兼职按2024多职业施法规则合并；
- 免费施展与法术位施展分开；
- 每回合至多通过施法消耗一个法术位，以turn_key和事件记录实施；
- 怪物/物品可使用独立资源池。

## 5. 成分与装备

### 5.1 手部模型

EquipmentSlots至少：main_hand、off_hand、armor、focus、worn。S与M判断读取真实持握状态；材料/法器手是否能同时完成姿势按法术成分规则执行。双手武器“攻击时需双手”与平时可短暂松手要用明确交互规则，而不是名称关键词。

### 5.2 材料

MaterialRequirement：标签/具体物品、数量、最低价值、是否消耗。材料包/法器只能替代无价且不消耗材料；具体材料成功施法后生成ItemConsumed。

### 5.3 护甲限制

穿着未受训护甲时，对适用力量/敏捷D20检定承受劣势且不能施法。训练来源应来自Grant集合，而非单职业静态映射。

## 6. 法术Effect DSL覆盖分类

| 类别 | 所需原子能力 | 例子 |
| --- | --- | --- |
| 直接伤害/治疗 | damage/heal、攻击/豁免、升环 | 火球术、疗伤术 |
| 持续修正 | roll modifier、AC/速度/属性覆盖、持续 | 祝福术、剑刃防护 |
| 状态控制 | apply condition、重复豁免、免疫条件 | 人类定身术、交友术 |
| 移动/传送 | push/pull/teleport、目的地合法性 | 雷鸣波、迷踪步 |
| 区域 | create zone、进入/开始回合tick | 沉默术、云雾术 |
| 召唤 | spawn entity、控制权、独立回合 | 召唤类法术 |
| 变形 | form override、HP池、能力替换 | 变形术 |
| 侦测/信息 | reveal、sense grant、查询权限 | 侦测魔法、识破隐形 |
| 创造/物件 | create object、持续和材质 | 光亮术、造物类 |
| 反应/中断 | trigger window、取消/修改事件 | 护盾术、法术反制 |
| 选择与分支 | player choice、conditional、repeat | 魔法飞弹分配、交友术条件 |

任何法术不得以`{"effect":"applied"}`作为完整实现。

## 7. 专注

- 开始新专注时结束旧专注；
- ConcentrationLink绑定施法者、来源法术和所有效果实例；
- 每个独立伤害源触发一次体质豁免，DC=max(10, floor(damage/2))且2024上限30；
- 失能、死亡、主动结束和规则指定条件结束专注；
- 失败时原子删除所有关联效果；
- 施法时间超过一动作且要求专注的法术，在施展期间也创建专注链接；
- UI展示当前专注来源和效果目标。

## 8. 特殊施法时序

- 护盾术：攻击命中后、伤害前开放反应；重新计算该攻击是否仍命中；
- 法术反制：观察到施法开始且满足距离/可见性时开放；
- 解除魔法：对活动效果实例进行能力检定或自动结束；
- 准备法术：准备动作时施展并消耗位、开始专注，触发时用反应释放；
- 长时间施法：每回合持续动作且维持专注，中断规则完整；
- 仪式：验证施法来源具备仪式能力，增加10分钟，不耗位。

## 9. 角色构筑领域模型

### 9.1 CharacterBuild

```text
SpeciesChoice
BackgroundChoice
ClassLevel[1]
AbilityAllocation
Skill/Tool/Language choices
Equipment package choices
Origin feat choices
Spell choices
Derived grants
```

每个选择保存ChoiceRecord与候选集合revision。最终角色不是只存字符串结果，而是保存grant来源，便于迁移和重算。

### 9.2 Grant与Feature

```yaml
id: feature.fighter.second_wind
level_granted: 1
resources:
  - id: second_wind_uses
    max: proficiency_bonus
    recharge: short_rest
commands:
  - type: UseFeature
    cost: bonus_action
    effects: [...]
```

Feature DSL应覆盖：资源、动作、反应、被动修正、替代检定、重掷、选择、触发、法术授予、精通授予。

## 10. 职业与升级

### 10.1 职业进度

每个职业定义1-20级：生命骰、主属性、豁免/技能/武器/护甲、起始装备、每级特性、资源公式、子职选择、法术进度、可替换选择。

升级服务：

1. 验证XP/里程碑与目标职业；
2. 验证兼职先决；
3. 增加对应职业等级；
4. 计算HP与生命骰；
5. 自动授予该级Feature并生成ChoiceRequest；
6. 处理ASI/专长、法术准备/替换、精通选择；
7. 重算衍生值和资源上限；
8. 原子提交LevelGained和Grant事件。

客户端不能传`new_features`自由列表。

### 10.2 子职业

所有职业在3级选择子职，但每个子职后续等级特性必须完整定义。子职可授予新动作、法术、资源和替换规则，复用同一Feature系统。

### 10.3 兼职

Character使用`class_levels`；PB基于总等级；HP按所升职业；熟练授予区分首职业和后续职业；Extra Attack等同名特性按规则不叠加；施法位按多职业规则；魔契术法独立。

## 11. 物种、背景、专长

### 11.1 物种

定义体型、速度、感官、生物类型、抗性、特性、固有法术及选择。所有效果进入Grant/Feature系统。

### 11.2 背景

定义属性加值候选、技能、工具、起源专长、装备/金币。创建器验证+2/+1或+1/+1/+1约束及选择数量。

### 11.3 专长

专长包含category、prerequisite、repeatable_key、选择和Feature效果。例如：

- 警戒：先攻加PB与战斗开始后的交换窗口；
- 幸运：PB数量资源池，掷骰前给予优势或攻击者劣势；
- 医疗师：操作动作、医疗包消耗、生命骰和治疗重掷；
- 魔法学徒：法术来源、施法属性、每日免费施展及法术位施展；
- 战斗风格：攻击/伤害/AC/反应等Modifier或Trigger。

## 12. 物品与装备

### 12.1 定义/实例分离

```text
ItemDefinition：规则数据
ItemInstance：唯一实例、拥有者、同调、充能、识别、诅咒
ItemStack：可堆叠数量
EquipmentSlot：当前穿戴/持握引用
```

### 12.2 护甲与盾牌

穿脱时间、力量要求、隐匿劣势、训练惩罚、盾牌操作均通过命令和效果。盾牌必须实际装备在手上才加AC。

### 12.3 魔法物品

同调前置、最多3件、充能、恢复时点、激活动作、法术施展、被动修正、诅咒与识别。物品效果同样产生Grant/Effect/Resource事件。

## 13. 内容编译流水线

```text
HTML原文
 -> 结构化提取（保留anchor和hash）
 -> 候选Definition（带confidence）
 -> Schema验证
 -> 人工/规则审校
 -> Definition compiler
 -> handler/effect graph
 -> generated tests
 -> CoverageManifest
 -> publish content pack
```

自动解析不能直接进入FULL。低置信度、复杂条件、正则未识别字段必须进入审核队列。

## 15. 完成门禁

- 所有PHB2024法术都有稳定ID和已审校Definition；
- 所有公开法术不存在LLM机械回退；
- 12职业1-20级、公开子职、物种、背景、专长均有Feature覆盖；
- 每个内容项至少一个机械测试；复杂项有场景测试；
- CoverageManifest中`DATA_ONLY/PARTIAL`内容不在complete模式API返回；
- 未知或homebrew内容必须显式建立独立Definition。
