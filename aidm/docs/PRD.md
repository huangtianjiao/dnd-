# PRD — AI DM（D&D 5E 跑团系统）

> 产品需求文档 v1.0 · 配套 `ARCHITECTURE.md`（架构）/ `BUILD.md`（搭建）/ `RULE_SPEC.md`（规则规格书）

## 1. 产品概述

一个以 **AI 担任 DM**、玩家扮演角色的 D&D 5E 跑团系统。AI 负责描述场景、演绎 NPC、裁决规则、推进战斗；玩家通过自然语言行动参与冒险。

**一句话定位**：基于 D&D 5E 不全书规则数据，用"硬性判定"保证规则准确、用 LLM 负责叙事的 AI 跑团引擎。

**项目背景**：已克隆官方开源规则书 `5echm_web`（8644 页 HTML + data.js 6238 条索引），并提炼为 `RULE_SPEC.md`（400 条结构化规则点，经 7 组并行审计复核）。

## 2. 目标与用户

| 项 | 说明 |
|----|------|
| 目标用户 | 想 AI 跑团的 D&D 5E 玩家 / DM；中文跑团社群 |
| 核心痛点 | LLM 跑团规则不准（混 2014/3.5e、臆测 DC、作弊骰子）；状态易失忆 |
| 核心价值 | **硬性判定**——掷骰/数值/规则全走代码，LLM 只在意图理解与叙事两端活动 |

## 3. 核心价值主张：硬性判定

判定准确性的本质是划死边界——LLM 碰都不能碰的步骤由代码执行：

| 步骤 | 负责 | 不可交给 LLM 的理由 |
|------|------|---------------------|
| 掷骰 d20 / 优劣势 / 大失败必出 | 🔒 代码 | LLM 倾向"给好结果"或算错 |
| 命中 vs AC / 豁免 DC / 伤害结算 / 状态效应计时 | 🔒 代码 | 比较与累加无歧义 |
| 法术位消耗 / 熟练加值 / HP 扣减与上限 | 🔒 代码 | 计数器与查表 |
| 理解玩家自然语言意图 | ✅ LLM | 语义理解 |
| 受规则约束地决定"是否检定/用哪个动作" | ✅ LLM（RAG 校验） | 创造性裁决 |
| 把判定结果讲成故事 | ✅ LLM | 叙事 |

**硬性判定链**：玩家意图 → [LLM]意图映射到判定模板 → [RAG]查规则校验参数 → [代码]掷骰/比较/算结果（硬性）→ [LLM]叙事+结构化状态指令 → [代码]执行状态更新。LLM 只在首尾，中间全代码。

## 4. 功能需求

### P0 — 引擎核心（硬性判定地基，不需 API）
- **骰子引擎**：d20 优劣势、NdM+K 表达式、d100/d3、重击骰翻倍、属性调整值、熟练加值 ✅（dice.py 已完成）
- **D20 检定**：属性检定 / 豁免 / 攻击命中（天然20必出、天然1必失）
- **伤害结算**：抗性→易伤→免疫顺序、HP/临时HP/死亡豁免/治疗
- **状态效应**：14 种状态（倒地/擒抱/束缚/中毒/麻痹/震慑/昏迷/目盲/耳聋/隐形/魅惑/恐慌/石化/失能）+ 力竭累加
- **装备数据**：护甲表(13套)、武器表(38件)、词条/精通、钱币

### P1 — 状态层（持久化）
- 角色卡（属性/技能/HP/法术位/物品/特性）
- 战役/场景/战斗状态（先攻顺序、回合、效应计时、专注维持）
- rolling summary（防上下文失忆）
- SQLite 单文件存档（存档=拷文件）

### P2 — 知识层（RAG，需 embedding API）
- data.js 6238 条 → 切片 → Qdrant 向量化
- 语义检索 + 标签过滤
- **校验器**：用检索到的规则原文校验 LLM 判定参数，冲突驳回

### P3 — 编排层（LangGraph，需 LLM API）
- 图式状态机：意图分类 → 检索 → 校验 → 骰子 → 叙事 → 状态更新
- 条件边（校验失败重走）、checkpointer 持久化（=跑团存档）
- human-in-the-loop（关键判定暂停确认）

### P4 — API 层
- FastAPI：对话、角色卡、骰子、战斗状态端点
- 结构化状态指令（JSON schema）

### P5 — 前端
- Next.js + shadcn/ui：对话区、骰子动画/日志、角色卡、战斗追踪器

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| 准确性 | 规则判定 100% 走代码，可审计回溯（每轮记骰子+状态变更+规则引用） |
| 可存档 | SQLite 单文件，存档即拷贝；可中断恢复（LangGraph checkpoint） |
| 可追溯 | 完整跑团日志（玩家输入+AI回复+骰子明细+RAG引用） |
| 低延迟 | 骰子/状态本地即时；仅叙事走 LLM |
| 离线 | P0/P1 完全离线；P2/P3 需 API（embedding+LLM） |

## 6. 范围边界

**做**：D&D 5E 2024 核心规则判定（玩家手册2024/城主指南2024/DM速查/术语汇编）、AI DM 编排、跑团存档。
**不做**（本期）：多人联机跑团、3D 地图/VTT、语音输入、完整怪物/法术数据库索引（仅规则判定所需）。

## 8. 成功验收标准

1. 问"擒抱怎么判""火球术伤害"→ RAG 查得准（规则原文）
2. 掷一次攻击：d20+命中 vs AC，命中走伤害骰，全程代码、可审计
3. 打一场标准战斗：先攻/回合/状态效应/专注维持全代码管理
4. 一次长跑团（20+轮）剧情不丢（rolling summary）、状态不乱
5. 关键判定可暂停让 DM 确认（HITL）
