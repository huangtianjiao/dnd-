# 前端设计文档 — AI DM VTT 界面

> 基于 `DND5e_UI_交互原型.html`（2199行交互原型）+ 规则书数据 + 后端 API 设计。
> 目标：将原型转化为与后端 API 对接的可运行前端。

## 二、三栏布局详解

### 左栏 — 角色卡面板（220px）

| 组件 | 功能 | 数据来源 |
|------|------|----------|
| Party Bar | 队伍成员头像列表，点击切换当前角色 | `GET /character/{id}` |
| Character Portrait | 当前角色名/种族/职业/等级 | 同上 |
| HP Section | HP血条（红→绿渐变）+ 当前/最大HP | 同上 |
| AC/Speed/Initiative | 三个数值方块 | 同上 |
| Ability Grid | 6属性 2×3 网格（力/敏/体/智/感/魅），显示值和调整值 | 同上 |
| Skill List | 技能列表，熟练项前有圆点标记 | 同上 |
| Spell Slots | 法术位格子（可用=蓝色/已用=灰色），点击消耗 | 同上 |
| Death Save Tracker | 死亡豁免计数器（3成功稳定/3失败死亡），HP=0时显示 | 同上 |
| Condition Tracker | 状态标签（中毒/专注/倒地/恐惧/束缚/目盲/祝福/灵感），可添加/移除 | 同上 |
| Concentration Track | 当前专注法术名称+打断专注按钮 | 同上 |
| Features & Actions | 职业特性列表（神圣感知/圣疗/神圣伤害），点击使用 | 同上 |
| Hit Dice | 生命骰格子（d8×3），点击掷骰恢复HP | 同上 |
| Inventory & Equipment | 物品栏列表，已装备项前有绿点 | 同上 |

### 中栏 — 主舞台（flex:1）

| 组件 | 功能 | 显示条件 |
|------|------|----------|
| Initiative Bar | 先攻序列卡片（当前回合高亮琥珀色），显示轮次 | 战斗模式 |
| Tactical Grid | 10×6 方格战术地图，玩家=紫色/敌人=红色/墙壁=深灰/困难地形=琥珀色 | 战斗模式 |
| Combatant HP | 各参战者迷你HP条（玩家=蓝框/敌人=红框） | 战斗模式 |
| Narrative Area | 叙事日志，6种消息类型（DM/玩家/NPC/骰子/伤害/系统） | 始终显示 |
| Action Panel | 战斗动作按钮组（移动/动作/附赠/反应/结束回合） | 战斗模式 |
| Quick Actions | 快捷检定按钮（调查/感知/潜行/运动/洞悉/生存） | 探索/社交模式 |
| Player Input | 玩家自由输入框 + 发送按钮 | 始终显示 |

### 右栏 — 骰子与日志（240px）

| 组件 | 功能 |
|------|------|
| Tab Header | [骰子] [规则参考] 切换标签 |
| Dice Roller | 骰子网格（d20/d4/d6/d8/d10/d12/d100/2d6），优势/劣势切换，修饰值输入，掷骰结果显示 |
| Action Log | 时间戳 + 动作记录列表 |
| Rest Buttons | [短休1h] [长休8h] 按钮 |

## 三、消息类型设计

叙事区域支持 6 种消息类型，每种有独立的视觉样式：

| 类型 | CSS类名 | 样式特征 | 用途 |
|------|---------|----------|------|
| DM叙事 | `.msg-dm` | 白底蓝左边框，衬线字体 | DM描述场景/叙述结果 |
| 玩家消息 | `.msg-player` | 紫底圆角右对齐 | 玩家描述行动 |
| NPC对话 | `.msg-npc` | 琥珀底左对齐 | NPC说话/回应 |
| 骰子结果 | `.msg-roll` | 绿色卡片居中，大号数字 | 掷骰结果展示 |
| 伤害提示 | `.msg-damage` | 红色卡片居中 | 伤害/治疗数值 |
| 系统消息 | `.msg-system` | 灰色居中，两侧破折号 | 先攻序列/回合切换/模式切换 |

## 四、模式切换机制

Top Bar 有三个模式按钮：[探索] [战斗] [社交]

| 模式 | 显示的组件 | 隐藏的组件 |
|------|-----------|-----------|
| 探索 | Quick Actions, Narrative Area, Player Input | Initiative Bar, Tactical Grid, Combatant HP, Action Panel |
| 战斗 | Initiative Bar, Tactical Grid, Combatant HP, Action Panel, Narrative Area, Player Input | Quick Actions |
| 社交 | Quick Actions, Narrative Area, Player Input | Initiative Bar, Tactical Grid, Combatant HP, Action Panel |

## 五、骰子掷骰器设计

### 骰子网格
- 8个骰子按钮：d20, d4, d6, d8, d10, d12, d100, 2d6
- 点击后掷骰，结果显示在下方

### 优势/劣势切换
- 三个按钮：[正常] [优势] [劣势]
- 仅对d20生效
- 优势：掷两个d20取较高值
- 劣势：掷两个d20取较低值

### 修饰值输入
- 数字输入框，默认0
- 掷骰结果 = 骰子点数 + 修饰值

### 掷骰结果显示
- 大号数字显示最终结果
- 下方显示分解：`[骰子点数] + 修饰值`
- 优势/劣势时显示两个骰子的值

## 六、法术书弹窗设计

### 弹窗结构
- Modal Header：标题"法术书 — 角色名 (职业 Lv.N)" + 关闭按钮
- Modal Body：法术卡片列表

### 法术卡片
- 卡片头部：法术名称 + 环阶标签
- 卡片元数据：施法时间 / 施法距离 / 成分 / 持续时间
- 卡片描述：点击展开/收起
- 施放按钮：仅1环法术显示，点击后施放

## 七、战斗系统UI设计

### 先攻序列条
- 水平排列的先攻卡片
- 每张卡片显示：先攻值 + 角色名
- 当前回合的卡片高亮（琥珀色背景+边框）
- 已完成回合的卡片半透明

### 战术网格
- 10列×6行的方格地图
- 每格24×24像素
- 格子类型：
  - 玩家位置：紫色背景
  - 敌人位置：红色背景
  - 墙壁：深灰色背景
  - 困难地形：琥珀色背景
  - 空地：浅灰色背景，可点击移动

### 参战者HP条
- 水平排列的迷你HP条
- 每个参战者显示：名称 + HP条 + HP数值
- 玩家=蓝色边框，敌人=红色边框

### 动作面板
- 三行按钮组：
  1. 移动：[移动 30ft] [疾步 +30ft]
  2. 动作：[攻击] [施法] [闪避] [协助] [脱离] [躲藏]
  3. 附赠/反应/结束：[专用附赠] [反应] [结束回合]
- 已使用的动作按钮变灰+删除线

## 八、状态追踪器设计

### 状态标签
- 支持的状态：中毒/专注/倒地/恐惧/束缚/目盲/祝福/灵感
- 每种状态有独立的颜色方案
- 可添加（下拉菜单选择）和移除（点击x）

### 专注追踪器
- 显示当前专注的法术名称
- 显示最大持续时间
- "打断专注"按钮

### 死亡豁免追踪器
- HP=0时自动显示
- 两行圆点：成功（3个）/ 失败（3个）
- "掷死亡豁免 d20"按钮

## 九、休息机制UI设计

### 休息按钮
- 右栏底部两个按钮：[短休 1h] [长休 8h]
- 点击后触发对应的后端API

### 短休流程
1. 点击"短休 1h"按钮
2. 系统提示："你要消耗几个 Hit Dice？你当前有 3d8 可用。"
3. 玩家选择消耗数量
4. 系统掷骰恢复HP
5. 更新HP显示

### 长休流程
1. 点击"长休 8h"按钮
2. 系统执行长休效果：
   - HP恢复至满值
   - 恢复全部Hit Dice的一半
   - 恢复所有法术位
   - 恢复所有职业特性使用次数
3. 更新所有显示

## 十、与后端API的对接

### API调用映射

| 前端操作 | 后端API | 说明 |
|----------|---------|------|
| 开始新游戏 | `POST /campaign` + `POST /character` + `POST /open` | 创建战役+角色+DM开场 |
| 继续游戏 | `GET /campaigns` → 选一个 → `GET /campaign/{id}/state` | 列出战役+加载状态 |
| 加入房间 | `POST /join` → WebSocket连接 | 加入已有战役 |
| 玩家输入行动 | `POST /chat` | 走判定链→返回叙事+骰子+选项 |
| 获取角色卡 | `GET /character/{id}` | 返回完整角色数据 |
| 获取场景 | `GET /scene/{campaign_id}` | 返回当前场景信息 |
| 获取战斗状态 | `GET /combat/{campaign_id}` | 返回先攻序列/轮次/参战者 |
| 怪物检索 | `GET /monster/{name}` | 返回怪物属性块 |
| AI生成世界设定 | `POST /generate_setting` | 返回AI生成的世界设定文本 |
| HITL恢复 | `POST /chat/resume` | DM确认后继续判定链 |

### WebSocket消息类型

| 消息类型 | 触发条件 | 前端处理 |
|----------|----------|----------|
| `join` | 新玩家连接 | 更新玩家列表 |
| `leave` | 玩家断开 | 更新玩家列表 |
| `result` | 判定链完成 | 显示DM叙事+骰子结果+3个选项 |
| `processing` | 判定链开始 | 显示"⏳ {player} 正在判定..." |
| `player_acting` | 其他玩家行动 | 显示"⟳ {player} 正在: {action}" |
| `scene_update` | 场景变化 | 更新场景面板 |
| `combat_update` | 战斗状态变化 | 更新先政序列/参战者HP |
| `character_update` | 角色状态变化 | 更新HP/AC/法术位 |
| `turn` | 回合切换 | 更新当前回合指示器 |
| `error` | 错误发生 | 显示错误消息 |

## 十一、响应式设计

### 断点
- `>1200px`：三栏完整布局
- `768px-1200px`：左栏折叠为图标条，右栏移至底部
- `<768px`：单栏布局，通过底部标签切换面板

### 移动端适配
- 角色卡面板改为横向滚动卡片
- 战术网格支持触摸拖拽
- 骰子掷骰器改为全屏弹窗
- 叙事区域占满屏幕

## 十三、交互细节

### 骰子动画
- 点击骰子按钮后，按钮缩小（`transform: scale(0.92)`）
- 结果数字从0滚动到最终值
- 优势/劣势时两个骰子同时滚动

### HP血条动画
- 血条宽度变化使用 `transition: width 0.4s ease`
- 受伤时血条闪烁红色
- 治疗时血条闪烁绿色

### 先攻卡片动画
- 当前回合的卡片有脉冲效果
- 回合切换时卡片滑动到下一个位置

### 法术卡片展开动画
- 点击法术卡片后，描述区域展开
- 使用 `max-height` 过渡实现平滑展开

## 十四、技术实现方案

### 方案A：HTML单页（当前实现）
- 优点：无需构建工具，FastAPI直接托管
- 缺点：代码量大，维护困难
- 适用：快速原型验证

### 方案B：Next.js + Tailwind（推荐）
- 优点：组件化开发，类型安全，SSR支持
- 缺点：需要Node.js构建环境
- 适用：正式产品开发

### 方案C：Vue 3 + Element Plus
- 优点：中文生态友好，组件丰富
- 缺点：与后端Python生态不同构
- 适用：团队熟悉Vue的情况
